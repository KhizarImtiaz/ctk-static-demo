1 · Purpose — why this widget

Compliance staff have questions like "What are beach access laws in Florida?" The answers live in CTK's big compliance library, spread across many pages. This widget lets them just ask and get an instant, trustworthy answer.

  • Instant answers in plain English — no digging through pages.
  • Trust — every answer shows its source citations (it never makes law up).
  • Embed anywhere — drop it into the existing Compliance app with one snippet.
  • Reuses CTK's own content — the same compliance library, for every customer.
  • On-prem AI — the model runs in-house, so client data stays private.
2 · Complete know-how — in one paragraph

The Widget is only the chat box. When you ask, it sends your question to the Backend API. The Backend finds the most relevant compliance content (a fast search), hands it to the MCP, which prompts the LLM to write a clean, cited answer. The answer streams back to the widget with clickable citations. The AI never touches the database — it only reads the small set of passages it's given, so answers stay grounded and safe.

Key idea (RAG): the content is searched first, then the AI writes using only what was found — that's why answers are accurate and every claim can be cited.

4 · Data flow — step by step

Setup (once, in the background): the Compliance DB content is turned into a searchable index (FAISS). Refreshed when content changes.

User asks a question in the widget (e.g. "beach access laws in Florida").
Widget sends it to the Backend API (with state + line-of-business context), over a streaming connection.
Backend searches the index and pulls the most relevant compliance passages + their source info.
MCP builds the prompt (passages + rules + chat history) and calls the LLM.
LLM writes a structured, cited answer, emitting [ref: title | source | description | url] markers.
Backend streams the answer back + a clean sources list, and saves the chat to history.
Widget shows the answer, turns [ref:] markers into clickable citation chips, and fills the References panel.
5 · Each part explained (Widget · API · MCP · LLM · DB)
🗨️ Widget

What: the chat box users see and type in.

Does: shows the question, streamed answer, inline citation chips, References panel, chat history. Embedded via a 1-line snippet (iframe) into the Compliance app.

Does NOT: no AI, no database, no secrets — it only calls the Backend.

Tech: React · standalone repo · host-agnostic

⚙️ Backend API

What: the front door + brain coordinator (AI-CTK-NLP).

Does: receives the question, searches the compliance index, asks the AI (via MCP), streams the cited answer back, saves chat history. The only thing the widget talks to.

Why here: keeps LLM keys + data access private (never exposed to the browser).

Tech: FastAPI · FAISS · Postgres · SSE streaming

🧩 MCP

What: the orchestrator between the Backend and the model.

Does: chooses the right tools + prompt, feeds the found passages + rules to the LLM, and enforces the citation format so answers are always sourced.

Tech: tool/prompt layer (MCP)

🧠 Custom LLM

What: the AI that writes the answer.

Does: reads the question + the found compliance passages and writes a clear, structured, cited answer in plain English.

Key: runs on-prem/in-house (data control); it only sees the passages it's given — never the database.

Tech: proprietary on-prem model (via an adapter)

🗄️ Data (DB + Index)

What: the source of truth — CTK's central compliance content.

Content DB: the shared DB* tables — state-law summaries, citations, sources, charts. Same library for every customer.

Search index: that content turned into a FAISS vector index for fast, meaning-based search.

History DB: Postgres stores chats, projects, and feedback.
